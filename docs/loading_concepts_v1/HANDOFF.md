# 로딩 마스코트 「카드 메이드」 인수인계

작성일: 2026-11-06 · 대상 프로젝트: 미소녀 카드게임 / Godot 4.7

## 1. 결정사항과 현재 상태

사용자는 두 로딩 마스코트 중 **A 시안 ‘카드 메이드’를 선호하여 이 시안의 인수인계 문서 작성을 요청했다.** 이후 작업은 메이드를 중심으로 진행한다. B 시안 ‘왕관 공허젤리’는 비교 자료로 보관한다.

현재 결과물은 **8프레임 콘셉트 시트와 독립 HTML 미리보기**다. 최종 게임용 에셋 정리, 게임 로딩 화면 연결, 실행 파일 반영은 아직 진행하지 않았다. 디자인 선택과 구현 완료를 구분할 것.

이 문서의 ‘현재’ 항목은 제작된 파일과 확인한 프로젝트 코드 기준이다. ‘권장’ 항목은 다음 담당자를 위한 제안이며 사용자가 확정한 추가 사양은 아니다.

## 2. 디자인 의도

검정 바탕 위의 흰색 그래픽으로, 짧은 대기 시간에도 알아보기 쉬운 작은 메이드 마스코트다. 원래 요청의 참고 이미지는 젠레스 존 제로의 로딩 그래픽으로, **흑백 대비·간결한 배치·작은 캐릭터의 반복 동작**을 참고했다. 참고작의 캐릭터나 로고를 그대로 사용한 것은 아니다.

유지할 시각 요소:

- 둥근 단발머리, 메이드 머리장식, 뒤로 나온 리본.
- 작은 앞치마 드레스와 둥근 구두가 만드는 짧고 귀여운 비례.
- 가슴 앞에 양손으로 꼭 안은 커다란 카드.
- 카드 중앙의 검정 네 갈래 별과 흰색 카드 테두리.
- 흰색 면과 검정 음영부만으로 읽히는 단순한 그래픽.

카드를 안고 제자리에서 가볍게 뛴다. 몸의 상승·착지에 머리, 리본, 치맛단이 조금 늦게 따라오도록 설계했다. 캐릭터를 좌우로 이동시키는 연출보다 **한 자리에서 작게 반복되는 동작**이 기준이다.

## 3. 전달 파일

아래 경로는 프로젝트 루트 기준이다. 문서와 원본은 같은 폴더에 있다.

| 파일 | 용도 |
|---|---|
| `docs/loading_concepts_v1/a_card_maid_sheet.png` | 선택된 A 시안 원본, 4열×2행 |
| `docs/loading_concepts_v1/preview.html` | 로딩 문구 옆에서 두 시안을 재생하는 독립 미리보기 |
| `docs/loading_concepts_v1/sheets.json` | 원본 크기, 재생 속도, 프레임별 정수 픽셀 영역 |
| `docs/loading_concepts_v1/PROMPTS.md` | 내장 `image_gen`으로 제작한 전체 생성 프롬프트. 메이드는 A 항목 |
| `docs/loading_concepts_v1/README.md` | 두 시안의 최초 전달 설명 |
| `docs/loading_concepts_v1/b_void_jelly_sheet.png` | B 비교 시안. 메이드 구현에는 필요 없음 |

미리보기는 `preview.html`과 PNG 두 장을 같은 폴더에 둔 채 브라우저에서 연다. 재생/정지, 한 프레임 이동, 4~12fps 조절을 지원한다. 현재 HTML은 두 PNG를 모두 불러오므로 B 파일을 지우면 로딩이 완료되지 않는다. 메이드 전용으로 변경할 때는 HTML의 이미지 목록과 두 번째 캔버스도 함께 정리한다.

레이어 분리 원본, 리그, 개별 프레임 PNG, 투명 PNG, GIF, 게임용 애니메이션 리소스는 아직 없다. PNG를 편집 가능한 레이어 파일로 오해하지 말 것.

## 4. 현재 시트 사양

| 항목 | 현재 값 |
|---|---|
| 원본 크기 | 1774×887px |
| 배치 | 4열×2행, 총 8프레임 |
| 순서 | 위쪽 왼쪽부터 0~3 → 아래쪽 왼쪽부터 4~7 → 0 |
| 기본 속도 | 8fps, 프레임당 125ms |
| 루프 길이 | 1초 |
| 배경 | 검정 포함, 불투명 PNG. 알파 없음 |
| 색감 | 흑백 그래픽. 가장자리 안티앨리어싱 등 중간 톤은 있을 수 있음 |
| 문구 | 시트에 없음. `NOW LOADING`과 `VOID DEFENSE`는 HTML에서 별도 표시 |

원본은 가로·세로가 열·행 수로 나누어떨어지지 않는다. 현재 미리보기는 각 셀 경계를 반올림하여 아래 영역을 사용한다. 좌표 원점은 PNG의 왼쪽 위이며 인덱스는 0부터다.

| 프레임 | x | y | 폭 | 높이 | 동작 의도 / 후속 정리 기준 |
|---|---:|---:|---:|---:|---|
| 0 | 0 | 0 | 444 | 444 | 카드를 안은 기본 자세 |
| 1 | 444 | 0 | 443 | 444 | 살짝 웅크리며 점프 준비 |
| 2 | 887 | 0 | 444 | 444 | 몸이 펴지며 상승 |
| 3 | 1331 | 0 | 443 | 444 | 공중의 가장 높은 지점 |
| 4 | 0 | 444 | 444 | 443 | 하강, 리본은 뒤늦게 따라옴 |
| 5 | 444 | 444 | 443 | 443 | 착지하며 충격 흡수 |
| 6 | 887 | 444 | 444 | 443 | 몸과 옷자락의 반동 정리 |
| 7 | 1331 | 444 | 443 | 443 | 기본 자세로 복귀, 다음 0과 연결 |

동작 설명은 설계 의도다. AI 생성 시트의 모든 실루엣·간격·기준점이 최종 애니메이션 수준으로 정리됐다는 뜻은 아니다. 특히 **7→0 연결**을 실제 재생으로 확인해야 한다. 끝에 0번을 한 장 더 붙이면 해당 자세가 두 배로 머무를 수 있으므로 기본 구성은 8장으로 유지한다.

## 5. 게임용 에셋 정리 작업

원본은 보존하고 별도 버전으로 작업한다. 다음 순서를 권장한다.

1. 원본 좌표로 8장을 분리한다. 셀 크기 차이는 여백으로 흡수하고, 매 프레임을 내용물 경계에 맞춰 자동으로 잘라내지 않는다.
2. 동일한 크기·카메라·좌우 중심을 유지한다. 접지 자세의 발 기준선은 맞추되, 점프의 의도된 상하 움직임까지 지우지 않는다.
3. 얼굴, 손 두 개, 카드 모양과 별, 구두, 머리장식, 리본의 형태가 프레임마다 불필요하게 바뀌지 않도록 정리한다.
4. 착지의 눌림과 리본의 지연을 다듬고 7→0의 위치·표정·리본 연결을 확인한다.
5. 같은 크기의 셀로 다시 배치한다. 작업용 제안은 **셀 448×448px, 4×2 시트 1792×896px**다. 원본 셀을 무조건 확대하지 않고 여백과 배치를 정리할 수 있는 규격이다. 확정 규격은 아니다.
6. 검정 로딩 배경만 사용할 때는 현 불투명 방식도 가능하다. 투명 에셋이 필요하면 원본을 보존한 채 별도로 제작한다. 검정을 일괄 투명 처리하면 눈·머리 경계·카드의 별처럼 필요한 검정 디테일까지 사라질 수 있으니 분리 기준을 확인한다.

최종 게임용 파일의 권장 위치는 `assets/textures/loading/`이다. **현재 `docs/*`는 내보내기 제외 대상**이므로 게임 코드에서 문서 폴더의 PNG를 직접 참조해 끝내지 않는다.

## 6. 화면 배치와 Godot 연결 방향

현재 프로젝트는 1920×1080 기준이다. `project.godot`의 화면 확장 설정과 `scripts/scene_switcher.gd`의 씬별 비율 처리를 고려해 화면 가장자리에서 잘리지 않도록 배치한다.

권장 구성:

- 검정 전체 화면 위에 로딩 문구와 메이드 애니메이션을 배치한다.
- 문구와 캐릭터를 별도 요소로 두어 글꼴·언어·여백을 조절할 수 있게 한다. HTML의 `VOID DEFENSE`는 미리보기용이며 전체 게임의 확정 로딩 문구가 아니다.
- 최초 비교 기준으로 미리보기와 같은 캐릭터 셀 표시 크기 146×146px를 사용할 수 있다. 실제 게임에서는 더 작은 크기에서도 카드의 별·얼굴·리본이 읽히는지 검수한다.
- 동일 셀로 정리한 최종 시트를 애니메이션 리소스로 구성하고, 0~7 순서·8fps·루프 재생을 기본으로 한다. 현 원본을 바로 사용해야 한다면 `sheets.json`의 개별 영역을 사용한다.
- 로딩 화면의 리소스는 대상 씬의 무거운 작업보다 먼저 준비한다. 대기 화면이 떠 있어도 메인 스레드가 오래 막히면 애니메이션은 멈출 수 있다.

### 현재 씬 전환 코드에서 확인한 점

`scripts/scene_switcher.gd`는 자동 로드되는 `CanvasLayer`다. `_ready()`에서 `SCENES`의 씬들을 동기 `load()`하여 `_packed`에 저장하고, `switch_to()`에서 `change_scene_to_packed(_packed[i])`로 전환한다.

따라서 다음 담당자는 먼저 로딩 화면이 필요한 구간을 정해야 한다.

- **초기 실행:** 현재는 씬 선행 로드가 시작 시점에 있다. 이 작업 중에도 애니메이션이 움직이게 하려면 최초 표시 시점과 로드 방식을 함께 검토해야 한다.
- **모드 이동:** 씬 파일은 이미 캐시되어 있어도 씬 생성·초기화에 시간이 걸릴 수 있다. 전환 전후의 실제 대기 구간을 측정하고 연결한다.

애니메이션을 붙이는 것만으로 기존 동기 작업이 비동기가 되지는 않는다. 로딩 표시를 먼저 렌더하고, 무거운 작업이 렌더 갱신을 막지 않도록 구성한다. 실제 로딩이 짧으면 루프 도중 종료할 수 있게 하고, 한 주기를 채우기 위한 강제 대기 시간은 현재 사양에 포함하지 않는다. 로딩 실패 시에는 무한 반복만 남지 않도록 실패 상태를 처리한다.

이 항목은 후속 구현 방향이며, 이 인수인계 작업에서는 씬 전환 코드를 수정하지 않았다.

## 7. 검수와 완료 조건

현재 확인한 것:

- 원본 PNG의 시각 확인 및 1774×887px 크기 확인.
- 미리보기 스크립트의 초기 렌더, 8프레임 순환, 정지, 수동 프레임 이동, 속도 조절, 원본 영역 범위 검사 통과. DOM·이미지·캔버스를 모의 객체로 대체한 실행 검사다.
- 브라우저 도구가 로컬 `file:` URL을 차단하여 실제 브라우저 화면에서의 재생 검수는 미완료.

후속 완료 조건:

- [ ] 선택된 메이드 디자인의 얼굴·손·카드·리본이 일관적이다.
- [ ] 8프레임의 셀 규격과 기준점이 정리되어 있다.
- [ ] 8fps에서 7→0이 튀거나 의도치 않게 멈추지 않는다.
- [ ] 실제 표시 크기에서 카드의 별과 얼굴이 읽힌다.
- [ ] 초기 실행/모드 이동 중 적용하기로 한 구간에서 실제로 움직인다.
- [ ] 로딩 완료 시 다음 화면으로 넘어가고, 실패 시 실패 상태를 표시한다.
- [ ] 실제 사용 파일이 `assets/` 아래에 있고 내보낸 게임에서도 표시된다.
- [ ] 프로젝트 지침에 따라 기존 `Windows Desktop` 프리셋으로 단일 `build/windows/KSC_Touch_Game.exe`를 갱신하고, 내보내기 오류와 에셋 포함 여부를 확인한다.

씬은 생성물이라는 `CLAUDE.md` 지침을 따르고, 후속 씬 변경은 해당 생성 절차를 통해 반영한다. 별도 로딩 데모용 실행 파일이나 내보내기 프리셋을 만들지 않는다.

## 8. 다음 담당자의 첫 작업

**`a_card_maid_sheet.png`와 `preview.html`을 열어 메이드 루프를 직접 확인한 뒤, 프레임 형태와 기준점을 다듬은 균일 셀 시트를 만든다.** 그다음 실제 대기 구간에 맞춰 Godot에 연결한다. 새로운 마스코트 시안을 다시 만드는 작업부터 시작할 필요는 없다.
