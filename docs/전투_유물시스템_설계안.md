# 전투 기본 구조 설계안 — "유물 성좌판" (인벤토리 배치형 자동 발동 시스템)

작성일: 2026-11-05
기준: 사용자 UI 목업(우측 육각 슬롯에서 번개·투사체가 적을 때리는 그림), `scripts/void_defense/vd_battle.gd` 의 실시간 자동전투 루프, `docs/VoidDefense_기획안.md`
리서치: 백팩 히어로 · 세피리아 · 백팩 배틀즈 · 더 바자 (출처는 맨 끝)

> 한 줄 요약: **영웅 4인의 실시간 자동전투는 그대로 두고, 그 위에 "유물 성좌판"을 얹는다.**
> 성좌판은 육각 셀 인벤토리이고, 유물은 전투 이벤트(타격·처치·시간·스킬)에 반응해 스스로 발동한다.
> 유물을 어디에, 어떤 방향으로, 무엇 옆에 두느냐가 발동 빈도·위력·효과 종류를 바꾼다. 배치는 전투 밖(배치 단계)에서만 손댄다.

| 코어 / 모듈 | 투사체가 나가는 "장치" 느낌에 맞음 | 미소녀·유적 세계관과 톤이 안 맞음 |
| 아티팩트 | 세피리아와 같은 단어 | 그대로라 비교당하기 쉬움 |

추천 조합:

- 개별 아이템: **유물(Relic)**
- 슬롯 보드: **성좌판(Constellation Board)** — 좌측 깃발의 별 문양, 유물 발동 시 반짝임과 묶인다. 육각 셀 하나가 별 하나.
- 배치 시너지 묶음: **성좌(Constellation)** — "번개 유물 3개가 한 줄 = 뇌운 성좌 완성" 처럼 세트 이름을 붙일 수 있다.
- 유물에 효과는 없고 주변만 강화하는 보조 조각(세피리아의 석판 역할): **인장(Seal)**

아래 문서는 유물 / 성좌판 / 인장 으로 쓴다.

## 1. 레퍼런스 분석 — 무엇을 가져오고 무엇을 버리나

### 1-1. 네 게임 비교

| | 백팩 히어로 | 세피리아 | 백팩 배틀즈 | 더 바자 |
|---|---|---|---|---|
| 전투 | 턴제, 에너지로 아이템 클릭 사용 | 실시간 액션 (플레이어 직접 조작) | **실시간 오토배틀** | **실시간 오토배틀** |
| 아이템 크기 | 1×1 ~ 1×4, 2×2, 비정형, 회전 | **전부 1칸** (석판만 회전) | 다칸 + 회전 | 1~3칸 (한 줄) |
| 배치 문법 | 인접/대각, 좌우 방향, 최상단 행, 빈칸 수, 무게(가라앉음/뜸), 포켓 분리, 저주, 마나 네트워크 | 석판 패턴(행/열/대각/인접/나이트)이 레벨 ±, 위치 제약(가장자리/최상단/양옆 빈칸), 태그 콤보 | **별 소켓**(아이템에 그려진 특정 칸에 놓인 이웃만 버프), 가방 조각 확장 | 좌우 인접, 크기 |
| 발동 | 클릭(온 유즈) + 매 턴/피격 시 패시브 | 타격/치명/패리/N초마다/대시/처치/피격/MP소모/방 진입 | **쿨다운** + 전투 시작/타격/빗나감/기절/치명/N회 타격/임계치(HP 50%↓, 열기 10)/**별 아이템 발동 시** | 쿨다운 + 조건 + 가속/둔화/빙결로 쿨다운 조작 |
| 성장 | 레벨업마다 가방 칸 추가(모양 선택) | 석판 합성으로 인벤 확장 | 가방 조각 구매 | 티어 업 |
| 루프 방지 | 턴제라 불필요 | — | 가속은 가산 합산, 상한 1000% | **모든 아이템에 내부 쿨다운** |

### 1-2. 가져올 것 (우리 전투와 궁합이 좋은 순서)

1. **쿨다운 + 이벤트 트리거 타입 분류** (백팩 배틀즈) — 우리도 실시간이라 그대로 맞는다. 사용자가 적은 "쿨타임 / 특정 캐릭터 n회 공격 / 적 n명 처치" 가 전부 이 분류 안에 들어간다.
2. **1칸 유물 + 패턴형 인장** (세피리아) — 육각 슬롯은 칸 수가 적고(7~19칸) 모양 퍼즐을 넣으면 UI가 복잡해진다. 유물은 1칸으로 두고, "어디에 두느냐"의 재미는 인장과 방향 소켓이 만든다.
3. **별 소켓 = 방향 소켓** (백팩 배틀즈) — 육각형은 변이 6개라 "이 변에 닿은 이웃만 강화"가 자연스럽고, 회전(6방향)이 의미를 가진다. 사용자 목업에서 번개 육각형이 특정 변 쪽으로 터지는 것과 그림이 같다.
4. **체인 트리거** (백팩 배틀즈 "별 아이템 발동 시 내 쿨다운 15% 당김", 더 바자 "다른 Tech 사용 시 2초 충전") — 배치가 "숫자 +1"이 아니라 **발동 순서와 리듬**을 만든다. 이게 세피리아보다 백팩 배틀즈가 더 보여주는 깊이다.
5. **레벨 = 인장 합산, 상한은 희귀도, ≤ -1 이면 비활성** (세피리아) — 수치 모델이 단순해서 구현·밸런싱이 쉽다.
6. **보드 확장을 플레이어가 고른다** (백팩 히어로) — "칸을 어디에 붙일지"가 그 자체로 빌드 결정.
7. **위치 제약** (세피리아·백팩 히어로) — 육각 보드는 행 대신 **링(중심/안쪽/바깥쪽)** 과 **축(3방향 줄)** 로 바꾼다.

### 1-3. 버릴 것

- 다칸 테트로미노 유물·회전 퍼즐 (백팩 히어로/배틀즈): 슬롯이 적고 실시간 전투 중 볼 여유가 없다. 인장 하나만 2~3칸 패턴 허용.
- 턴제 에너지·클릭 사용: 우리 전투는 자동. 플레이어 수동 입력은 궁극기 하나로 충분.
- 무게(가라앉음/뜸): 육각 보드에서 "아래"가 애매하다. 대신 **"링 밖으로 밀려남 / 중심으로 끌림"** 정도로 변형 가능하지만 1차에는 제외.
- 세피리아의 태그 20종: 너무 많다. 1차는 6종.

## 2. 전투 기본 구조

### 2-1. 두 개의 피해 경로

```
            ┌──────────────── 전장(아이소 보드) ────────────────┐
            │  영웅 4인 실시간 자동전투 (기존 vd_battle)         │
            │  이동 → 평타 → 마나 → 액티브 스킬                 │
            └───────────────┬───────────────────────────────────┘
                            │ 전투 이벤트 (타격·처치·스킬·피격·틱)
                            ▼
            ┌──────────── CombatEvents (시그널 버스) ────────────┐
            └───────────────┬───────────────────────────────────┘
                            ▼
            ┌──────────── 성좌판 런타임 ────────────────────────┐
            │  유물마다: 트리거 감시 → 조건 충족 → 효과 실행     │
            │  효과 = 투사체 / 상태이상 / 아군 버프 / 회복 / 자원 │
            └───────────────┬───────────────────────────────────┘
                            │ 투사체·효과는 슬롯 위치에서 전장으로 날아간다 (목업의 번개)
                            ▼
                         적 피해 → 다시 이벤트 (처치 등) → 체인
```

- 경로 A: 영웅 평타·스킬 (기존).
- 경로 B: 유물 자동 발동. **둘 다 같은 피해 함수(`take_damage`)와 같은 이벤트 버스**를 쓴다. 그래야 "유물이 처치한 적"도 "처치 시" 트리거를 울린다.

### 2-2. 유물 정의 (데이터 한 장)

유물은 코드가 아니라 데이터로 만든다. 세피리아 1.0이 유물 308종인 것처럼 수가 늘어나므로 처음부터 표 형태여야 한다.

```
relic:
  id: thunder_shard
  name: 뇌운 조각
  tags: [번개, 투사체]
  rarity: 2          # ★ 상한 = 레벨 상한
  trigger:
    type: counter    # cooldown | counter | event | threshold | chain | aura
    event: ally_attack
    who: any         # any | knight | gunner | mage | healer | linked_hero
    count: 4         # 아군이 4번 때릴 때마다
  effect:
    type: projectile
    target: nearest  # nearest | farthest | lowest_hp | random | all | line | area
    damage: [30, 45, 60]        # 레벨 0/1/2
    status: {shock: 2.0}
  ports: [NE, E]     # 이 변에 닿은 이웃에게 주는 것
  port_effect: {haste: 0.15}
  placement: none    # none | outer_ring | center | inner | empty_neighbors>=2 | not_adjacent_tag:번개
  internal_cd: 0.25
```

### 2-3. 트리거 분류 (백팩 배틀즈 + 세피리아 합본)

| 타입 | 예 | 비고 |
|---|---|---|
| **cooldown** | 3초마다 | 전투 시간 기준. 가속·둔화는 가산 합산 후 `cd = base / (1 + 가속 − 둔화)` (백팩 배틀즈 공식) |
| **counter** | 기사가 5번 때릴 때마다 / 아군 평타 10회마다 / 적 3명 쓰러질 때마다 | 전투가 끝나도 카운트 유지 여부는 유물별 플래그. 세피리아는 콤보 카운트를 유지한다 |
| **event** | 치명타 시 / 아군 스킬 시전 시 / 적 등장 시 / 아군 피격 시 / 전투 시작 시 / 방 클리어 시 | 이벤트당 1회. 내부 쿨다운 적용 |
| **threshold** | 아군 HP 50% 이하 "도달" 시(1회) / 적 화상 10중첩 "획득" 시(반복) | 백팩 배틀즈의 "reached(1회) / gained(반복)" 구분을 그대로 |
| **chain** | 소켓으로 연결된 유물이 발동하면 내 쿨다운 20% 당김 / 같이 발동 | 배치의 핵심. 깊이 제한 3 |
| **aura** | 상시. 소켓 이웃 피해 +10% / 영웅 공속 +5% | 발동 없음. 배치 바꿀 때 재계산 |

### 2-4. 효과 분류

| 타입 | 예 | 전장에서의 그림 |
|---|---|---|
| projectile | 가장 가까운 적에게 번개 60 | 슬롯 → 적으로 날아가는 투사체 (목업 그대로) |
| area | 가장 적이 많은 3×3 에 폭발 | 슬롯에서 떨어지는 낙하물 |
| status | 화상·감전·빙결·취약·둔화·기절 | 상태 아이콘, 틱 피해 |
| hero_buff | 기사 공격력 +20% 3초 / 전원 공속 +10% | 영웅 발밑 링 |
| heal_shield | 가장 다친 아군 회복 / 전원 보호막 | 힐 이펙트 |
| resource | 영웅 마나 +15 / 정수 +3 | 게이지가 찬다 |
| board | 넉백·끌어당김·소환 | 1차에서는 제외 |

### 2-5. 육각 성좌판의 배치 문법

좌표는 axial (q, r). 이웃 6칸, 축 3개(동서 / 북동-남서 / 북서-남동), 링(중심 = 0, 1, 2…).

| 문법 | 레퍼런스 | 우리 버전 |
|---|---|---|
| 인접 태그 수 | 백팩 히어로 "인접 보석마다" | "인접한 **번개** 유물 하나당 피해 +10%" |
| **방향 소켓** | 백팩 배틀즈 별 소켓 | 유물의 1~3개 변이 소켓. 그 변에 닿은 이웃만 받음. 회전으로 소켓 방향을 고른다 (6방향) |
| 줄(축) | 세피리아 행/열 석판, 백팩 히어로 "이 행의 무기" | "같은 줄의 투사체 유물 전부 가속 10%" |
| 링 조건 | 세피리아 가장자리/최상단, 백팩 히어로 최상단 행 | "바깥 링에서만 작동" / "중심에서만 작동" / "안쪽 링이면 비활성" |
| 빈칸 조건 | 백팩 히어로 "대각 빈칸마다", 세피리아 차가운 자물쇠 | "빈 이웃 하나당 피해 +15%" (큰 유물 하나를 외롭게 두는 빌드) |
| 인장(패턴 레벨) | 세피리아 석판 | 효과 없음. 패턴(인접 전부 +1 / 한 줄 +1 / 소켓 방향 +2, 반대편 −1) 로 레벨 가감 |
| 레벨 | 세피리아 | `lv = clamp(기본 + 인장 합, −∞, ★)`. lv ≤ −1 이면 비활성(회색), 카운트는 유지 |
| 저주·침식 | 백팩 히어로 저주, 세피리아 마음의 짐 | **공허 침식 셀**: 특정 보상·사건으로 보드에 생기는 막힌 칸. 이웃 −1. 정화 비용 지불로 제거. 세계관(공허가 유적을 잠식)과 맞물린다 |
| 보드 성장 | 백팩 히어로 레벨업 칸 추가 | 시작 7칸(중심+링1). 스테이지 클리어마다 바깥쪽에 붙일 칸 1~2개를 **3택1 모양**으로 제공. 최대 19칸(링2)·무한 모드 37칸 |
| 영웅 연결 (선택) | 백팩 히어로 CR-8 코어 | 보드 가장자리 6변 중 4변에 영웅 초상이 "닿아" 있고, 그 변에 인접한 유물은 그 영웅 소속(`linked_hero`). "연결된 영웅이 N회 공격 시" 트리거, 투사체가 영웅 손에서 나감 |

### 2-6. 루프·폭주 방지 (실시간이라 필수)

- 모든 유물에 `internal_cd` (기본 0.25초). 더 바자의 교훈.
- 체인 깊이 3. 같은 틱 안에서 A→B→C→A 금지 (방문 집합).
- 가속 합산 상한 +300%.
- 틱당 유물 발동 큐를 모아 한 번에 처리 (`_physics_process` 끝). 이펙트는 큐 순서대로 0.05초 간격으로 재생해 겹치지 않게.

### 2-7. 전투 밖 루프에 붙는 자리

현재 루프: PLACEMENT → SPAWNING → BATTLE → TRANSITION → CHOOSE_PATH → TRAVEL.

- **PLACEMENT**: 성좌판 편집 가능 (드래그·회전·인장 배치). 전투 중에는 잠금. 호버하면 영향받는 셀 하이라이트(백팩 히어로 방식).
- **TRANSITION(방 클리어)**: 유물 3택1 보상 (정수로 리롤). 보스 방은 인장 또는 보드 확장 칸.
- 짝수 스테이지 상점: 유물 구매·판매·정화·인장.
- 전투 중 1회 "재정렬" 소모품(CR-8 칩)은 후순위.

## 3. 1차 프로토타입 범위 (MVP)

목표: **배치에 따라 체감이 달라지는가**를 2주 안에 확인. 유물 12종, 인장 2종, 태그 4종, 보드 7칸 고정.

### 3-1. 태그 4종
번개(단일 투사체·감전) / 화염(지속 피해·광역) / 서리(둔화·빙결) / 수호(보호막·회복)

- **분배 인장**: 인접 6칸 +1.

### 3-4. 성공 기준
- 같은 유물 12개를 "아무렇게나" 둔 보드와 "소켓·줄을 맞춘" 보드의 DPS 차이 ≥ 1.8배.
- 플레이어가 호버 하이라이트만 보고 10초 안에 배치 이유를 설명할 수 있다.
- 무한 루프·초당 30회 이상 발동이 없다 (로그로 확인).

## 4. Godot 구현 구조 (기존 코드에 붙는 자리)

```
scripts/void_defense/
  vd_battle.gd        ← _apply_hit / _on_unit_died / skills.cast / _spawn_wave 에서 CombatEvents emit
  vd_unit.gd          ← take_damage 에 source(영웅|유물) 인자 추가, 상태이상(화상·감전·둔화) 타이머
  relics/
    relic_data.gd     ← 유물·인장·태그 정의 (VDData 처럼 Dictionary 상수, 나중에 .tres 로 이전)
    hex_board.gd      ← axial 좌표, 이웃·축·링 질의, 배치 검증, 레벨 계산, 확장
    relic_runtime.gd  ← 전투 중 인스턴스: 쿨다운·카운터·임계치·체인 큐·내부 CD
    relic_effects.gd  ← 효과 실행기: projectile/area/status/hero_buff/heal/resource → 기존 vfx·dmg_log 재사용
    relic_board_ui.gd ← 우측 성좌판 HUD: 드래그·회전·호버 하이라이트·발동 펄스·카운터 뱃지(목업의 +2)
  combat_events.gd    ← 시그널 버스 (autoload 또는 VDBattle 소유)
```

이벤트 목록 (1차): `battle_started`, `enemy_spawned(e)`, `ally_attacked(u, t, dmg, crit)`, `enemy_hit(t, dmg, source)`, `enemy_killed(e, source)`, `ally_damaged(u, dmg)`, `ally_hp_below(u, ratio)`, `skill_cast(u)`, `status_stacked(t, kind, stacks)`, `relic_fired(relic)`, `tick(dt)`.

투사체 출발점: 성좌판 HUD는 CanvasLayer 위에 있으므로 슬롯의 화면 좌표를 `camera` 역변환으로 월드 좌표로 바꿔 `fx_root` 에서 날린다 (목업처럼 HUD에서 전장으로 들어가는 그림).

### 6-2. 루프
- 런 시작: 보관함에 뇌운 조각·잉걸불. 설정 메뉴(톱니)에 "유물 전부 지급 (테스트)".

- 전투: 유물마다 게이지(카운트 n/4, 남은 초, 대기/사용됨)와 발동 펄스. 투사체는 슬롯 화면 좌표를 월드로 바꿔 전장으로 날아간다.
- 구역 클리어: 칸 1개 해금 → (확률) 침식 → 유물 3택1 패널(언제든 고를 수 있고, 여러 개가 줄을 선다).

### 6-3. 테스트에서 본 것
- 3방 자동 전투에서 뇌운·서리·정수병·잉걸불 모두 발동, 보드 규칙(잠긴 칸 거부·맞바꾸기·최상단 제약·침식 배치 거부·정화 비용) 전부 통과.
- 초반 방은 적 3~4마리에 전투가 3~4초라 평타가 8번도 안 나온다. **카운터형(4회)·쿨다운형(4초)은 초반에 1번 정도만 발동한다.** 유물 체감을 위해 초반 웨이브를 길게 하거나(적 수·체력), 카운트를 낮춰야 한다 → 다음 논의.
- 별 깃털은 아군이 50% 아래로 떨어질 일이 없어 0회. 임계치형은 후반용.

### 6-4. 투사체 연출 (`vd_relic_fx.gd` + `shaders/relic_ribbon.gdshader` · `relic_burst.gdshader`, 2026-11-05 셰이더판)
VFX연구 저장소의 방식(취향 로그: "SDF 하드 클립 말고 메시 + UV 흐름", "카툰 2~3톤 하드 쉐입")을 그대로 가져왔다. 공용 라이브러리 `shaders/vfx_lib.gdshaderinc`(노이즈·광선·해시)는 VFX연구에서 복사.

- **리본**: 슬롯 → 대상 2차 베지어 곡선을 따라 매 프레임 띠 메시(`MeshInstance2D` + `ArrayMesh` 스트립 56세그, UV x = 궤적, y = 폭)를 만들고, `relic_ribbon.gdshader` 가 그 위로 혜성 쉐입(둥근 머리 + 멱함수 꼬리)을 `head`/`len` 오프셋으로 흘린다. 결 노이즈가 진행 방향으로 패닝해 속도선이 되고(15fps 홀드 = 투스), 소멸은 꼬리 → 머리 알파 침식. 색은 4톤 하드 램프(테두리 → 몸통 → 코어 → 핫). `blend_premul_alpha` 라 몸통은 불투명 셀, 핫 코어만 HDR 1.15~1.25.
- **버스트**: 착탄 지점 쿼드(270px) + `relic_burst.gdshader`: 각도 노이즈로 깨진 블롭 3톤 + `vfx_rays` 방사 광선(블롭 바깥) + 얇은 충격 링, 첫 2프레임 순백 섬광, 후반 침식. 광선 수로 성격을 바꾼다(번개 9, 불 11, 서리 6 = 눈꽃).
- **만화 글자**: BANG! / BURN! / FREEZE! / GUARD! — 기울어진 Label 이 1.6배에서 튀어나와 0.16초 유지 뒤 위로 빠진다.
- **✦ 반짝이**: 하드 엣지 4각 별(테두리 색 외곽 + 흰 안쪽)이 궤적과 착탄 둘레에 팝.
- 피해·상태이상은 `impact` 시그널(착탄 순간)에서 적용. 대상이 움직이면 곡선 끝점이 따라간다.

## 7. 남은 논의 포인트

1. **초반 전투 길이**: 지금은 3~4초라 유물이 거의 안 돈다. 적 수·체력을 올릴지, 유물 카운트를 낮출지.
2. **보상 주기**: 기존 "매 3웨이브 특성 3택1" 자리를 유물 보상으로 바꿀지, 둘 다 둘지.
3. **기존 아이템 시스템과의 관계**: 기획안 3-5의 "8패밀리 합성 장비"는 영웅 스탯용으로 남기고, 유물은 별도 축으로 둘지. 둘 다 있으면 보상 종류가 세 가지(장비·유물·특성)라 과하다. **장비 합성을 빼고 유물로 통합**하는 안을 추천.
