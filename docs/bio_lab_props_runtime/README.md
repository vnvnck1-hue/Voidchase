# 바이오 연구실 프랍 실제 적용 · 런타임 v3

2026-11-13. 배양기·수경재배대·샘플 냉장 박스를 **현재 게임의 바이오 테마에 실제 배치**했다. 기존 블록 3종과 면별 렌더링은 유지한다.

[실제 전투 화면](actual_battle.png) · [전달용 에셋/코드 ZIP](bio_lab_runtime_v3.zip)

게임에서는 기존 단일 `build/windows/KSC_Touch_Game.exe`의 **설정 → 배경 테마 → 바이오 연구실**로 확인한다.

## 적용 내용

- 승인된 프랍 PNG 3종을 그대로 사용했다. 이번 작업에서 이미지 재생성·색 변경·무작위 회전·뒤집기·공중 부유를 추가하지 않았다.
- 큰 배양기는 오른쪽 뒤, 수경재배대는 왼쪽 뒤, 냉장 박스는 오른쪽 외곽을 우선한다. 실제 위치는 방 모양과 기존 통로를 고려해 결정한다.
- 전투 칸 밖의 빈 외곽에 바닥과 연결된 작은 받침을 만든다. 배양기 2×2, 재배대 1×2, 냉장 박스 1×1칸 기준이다. 받침은 같은 바이오 면별 텍스처를 사용한다.
- 장식 받침은 `VDMap.tiles`에 추가하지 않는다. 유닛 이동·아군 배치·스폰·필드 기믹의 칸 수와 위치는 그대로다.
- 받침 후보는 바깥 공기와 이어진 외곽으로 제한한다. 고리형 방 등의 닫힌 내부 구멍에는 프랍을 놓지 않는다.
- 새 복도/방이 장식 위치를 지나면 프랍과 받침을 먼저 제거한다. 새 방에는 프랍을 함께 올리고 도착 시 누락된 종류를 다시 배치한다.
- 바이오 테마에서만 표시한다. 공허·사막으로 바꿨다가 돌아와도 프랍을 중복 생성하거나 무작위로 움직이지 않는다.
- 바닥 뒤틀림 없이 접지점을 사용하며, 프랍은 바닥 뒤가 아닌 바닥 다음·유닛 이전에 그려 캐릭터를 가리지 않게 한다.
- 바이오 일반 전투/배치에서는 프랍과 받침을 포함한 방을 HUD 안쪽에 맞춘다. 다른 테마로 전환하면 기존 줌을 복원한다. 이동·패배·궁극기 연출에는 이 프랍 프레이밍을 강제하지 않는다.
- 받침 재질은 보드의 색 보정을 따라가고 프랍 재질은 뒤 프랍 보정을 따른다.

## 파일

- `scripts/void_defense/vd_bio_props.gd`: 외곽 탐색·프랍 배치·받침 렌더링·충돌 위치 제거·바이오 카메라 범위.
- `scripts/void_defense/vd_battle.gd`: 전투 생성/테마 선택/새 방 생성/도착/카메라/필드 색 보정에 연결.
- `assets/void_defense_bio/props/`: 게임에 직접 쓰는 배양기·재배대·냉장 박스 PNG.
- `assets/void_defense_bio/terrain/`: 게임 규격의 블록 3종, 9개 분리 면, 아틀라스·UV JSON.
- ZIP은 블록·프랍 PNG/아틀라스/JSON과 두 바이오 렌더링 스크립트, 적용 화면과 검수 기록을 포함한다. 현재 프로젝트에는 전투 연결까지 이미 반영돼 있다.

## 검증

- [placement_validation.json](placement_validation.json): 방 10종 × 4방향 = 40배치에서 3종 모두 배치, 전투 칸 침범 없음, 지도 변경 없음, 중복 생성 없음, 세 화면 비율의 HUD 안쪽 프레이밍 확인. 미래의 플레이 가능한 바닥이 겹치면 기존 장식 제거 확인.
- [gameplay_validation.json](gameplay_validation.json): 실제 Vulkan 전투·이동 2회 완료. 전장 → 십자로 → 기둥 광장 도착 시 각각 프랍 3종, 전투 칸과 겹침 0. 테마별 표시/숨김과 복귀 시 위치 유지 확인.
- [capture_props.json](capture_props.json): 최종 실제 전투의 프랍 3종 화면 좌표와 받침 좌표 기록.
- 테마 회귀 검증 실패 0, 기존 공허 보드와 다른 픽셀 0.
- 최종 단일 실행 파일 내보내기·포함 리소스·실행 확인은 [export_validation.json](export_validation.json)에 기록.
- 검증은 사용자 테마를 영구 변경하지 않고 별도 프로세스의 메모리 설정 또는 docs의 임시 프로필을 사용했다.
- 전투 러너 종료 시 이전 검수와 같은 ObjectDB/리소스 잔류 메시지는 로그에 보관했다. 프랍 검증 실패와 내보내기 오류는 별도로 확인했다.
