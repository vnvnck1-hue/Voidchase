# 클로드 인수인계 · 메이드 캐릭터 v2 스파인 조립

## 작업 목표와 현재 상태

v2의 투명 PNG 32개로 **새 Spine 캐릭터**를 조립한다. 사용자는 기존 캐릭터의 본이나 애니메이션을 재사용할 계획이 없다. 기준 포즈와 개별 파츠의 깨끗한 마감을 살리고, 이후 시선·고개·포니테일·팔다리를 독립적으로 움직일 수 있게 준비한다.

완료된 작업은 파츠 복원, PNG 내보내기, PNG 기준 포즈 재조립, 2D 관절·시선 테스트다. 이 패키지에서 **Spine 본·슬롯을 만드는 작업은 다음 단계**다. v1은 거친 경계 때문에 교체된 버전이므로 조립에는 v2 자산을 사용한다.

## 받을 파일

아래 경로는 이 문서가 있는 폴더 기준이다. ZIP을 풀면 같은 구조다.

| 파일 | 용도 |
| --- | --- |
| `images/*.png` | 투명 RGBA 파츠 32개. 머리·얼굴 15개, 목·의상 4개, 팔 6개, 다리 6개, 하트 1개 |
| `layout.json` | 파일명, 원본 캔버스상의 좌상단, PNG 크기, 회전축 후보, 그리기 순서, 홍채 클립 윤곽 |
| `setup-pose.png` | 1325 × 1790 기준 포즈. 새 Spine 프로젝트의 조립 결과를 비교할 기준 |
| `maid-layered.svg` | 같은 포즈의 편집용 아트워크. 팔·다리 겹침부나 외곽선 수정이 필요하면 이 파일에서 수정 |
| `parts-preview.png` | 밝고 어두운 배경에서 분리 파츠의 이름과 마감을 확인하는 시트 |
| `motion-check.png` | 회전과 시선 이동을 확인한 확대 캔버스의 2D 테스트 이미지 |

## 1. 기준 포즈 재현

캔버스는 **1325 × 1790**, 좌상단이 원점이다. X는 오른쪽, Y는 아래쪽으로 증가한다. `screen_left`와 `screen_right`는 화면 기준이다. 개별 PNG의 투명 여백도 크기와 좌표에 포함된다. 예를 들어 `hair_fringe.x = -5`, `hair_ponytail.y = -2`는 유효한 배치 값이다.

1. `layout.json.sprites`를 `drawOrder` 오름차순으로 순회한다. 작은 값이 뒤쪽이다.
2. 각 `images/<name>.png`를 원래 크기로 `(x, y)`에 그린다. 이때 `(x, y)`는 **PNG 좌상단**이다.
3. `clipTo`가 있는 두 홍채만 `layout.json.clipping[clipTo]`의 다각형으로 자른다. 다각형 좌표는 캔버스 기준이다. 다음 파츠를 그리기 전에 클립을 해제한다.
4. 기준 이미지와 비교할 때 하트를 표시한다. 하트는 애니메이션에서 독립적으로 켜고 끌 수 있게 둔다.

실제 저장된 32개 PNG를 이 규칙으로 다시 조립해 `setup-pose.png`와 대조했다. 전체 2,371,750픽셀 중 채널 차이가 8을 넘은 픽셀은 82개였다. SVG의 곡선 클립과 JSON의 36점 다각형 클립을 사용한 비교이므로, 마스크 가장자리에서 약간의 차이가 날 수 있다.

## 2. Spine에서 본과 이미지 배치

새 캐릭터 프로젝트의 이미지 폴더를 `images/`로 지정한다. 파일명과 슬롯명은 가능하면 확장자를 뺀 파츠 ID 그대로 쓴다. 아래 좌표는 **스케일 1, 셋업 회전 0°**를 기준으로 한다. 우선 이 상태로 조립해 기준 포즈를 맞춘 뒤 본 방향이나 길이, 가중치를 조정한다.

`layout.json`은 배치 매니페스트다. 자동 조립을 할 경우 이 값을 읽어 사용 중인 Spine 에디터 형식에 맞는 스켈레톤 JSON을 별도로 만들고, 에디터에서 열어 `.spine` 프로젝트로 저장한다.

### 좌표 변환

| 항목 | 계산 |
| --- | --- |
| 캔버스상 기준점 | 바닥 중앙 `O = (662.5, 1790)` 제안 |
| 캔버스 점 `P`의 Spine 월드 좌표 | `(P.x - O.x, O.y - P.y)` |
| 본의 셋업 로컬 위치 | 부모 피벗을 `A`, 현재 본 피벗을 `B`라고 하면 `(B.x - A.x, A.y - B.y)` |
| PNG 중심 `C` | `(x + width / 2, y + height / 2)` |
| 본 `B`에 붙일 이미지 중심의 로컬 위치 | `(C.x - B.x, B.y - C.y)` |

예를 들어 화면 오른쪽 아래팔 `forearm_cuff_screen_right`는 좌상단 `(628, 947)`, 크기 `383 × 432`, 팔꿈치 피벗 `(700, 1001)`이다. PNG 중심은 `(819.5, 1163)`, 팔꿈치 본 기준 이미지 오프셋은 **`(119.5, -162)`**다. 팔꿈치 본의 부모인 어깨 본 피벗 `(638, 849)`에 대한 로컬 위치는 **`(62, -152)`**다.

위 계산은 부모 축에 회전이나 스케일이 들어가기 전 기준이다. 본 방향을 기울인 상태로 생성할 경우 위치와 회전을 부모의 역변환으로 계산한다. `pivotInSprite`는 개별 PNG 좌상단에서 잰 회전축 확인용 좌표다. 실제 Region 배치는 PNG 중심과 슬롯 본의 차이로 계산한다. [Spine JSON 형식과 Region 속성](https://esotericsoftware.com/spine-json-format)

### 추천 본 계층

아래의 숫자는 조립 전 **캔버스 좌표**다. 실제 PNG 좌표는 항상 `layout.json`을 따른다. 리깅 테스트 후 회전축 후보를 조정할 수 있다.

```text
root (662.5, 1790)
├─ pelvis (395, 979)
│  ├─ skirt (395, 979)
│  ├─ thigh_l (301, 1174) → shin_l (320, 1428) → foot_l (372, 1682)
│  ├─ thigh_r (519, 1173) → shin_r (638, 1406) → foot_r (706, 1712)
│  └─ torso (413, 975)
│     ├─ apron (390, 965)
│     ├─ upper_arm_l (345, 836) → forearm_l (223, 903) → hand_l (129, 1060)
│     ├─ upper_arm_r (638, 849) → forearm_r (700, 1001) → hand_r (839, 1312)
│     └─ neck (550, 757) → head (550, 757)
│        ├─ ponytail (826, 190)
│        ├─ side_hair_l (222, 414) / side_hair_r (708, 409)
│        ├─ fringe (486, 274)
│        └─ iris_l (383, 575) / iris_r (623, 527)
└─ heart_fx (72, 370)
```

- `torso`에 `dress_bodice`, `skirt`에 `dress_skirt`, `neck`에 `neck_collar`를 붙인다. 앞치마, 머리카락, 팔, 다리 이미지는 대응하는 본에 각각 배치한다. 퍼프 소매는 위팔 PNG에, 흰 커프스는 아래팔 PNG에 포함되어 있다.
- `head`에 얼굴 바탕, 머리 장식, 양쪽 흰자와 두 클립을 붙인다. 홍채는 각 홍채 본에 붙인다. 눈꺼풀·눈썹·입은 우선 `head`에 배치하고, 움직임이 필요하면 `layout.json`의 각 피벗에 하위 본을 둔다.
- 포니테일은 하나의 완성된 파츠다. 루트 회전을 먼저 확인하고, 길이를 따라 추가 변형이 필요할 때만 메시와 가중치를 적용한다.

### 슬롯 그리기 순서와 홍채 클립

본 계층과 슬롯의 앞뒤 순서는 별개다. `layout.json`의 32개 순서를 그대로 유지하고, 각 홍채 바로 앞에 해당 클립 슬롯만 추가한다. 예를 들어 포니테일은 `head` 하위 본을 따라가지만 그림 순서는 맨 뒤다. 왼팔은 몸 뒤, 오른팔은 앞치마 앞으로 배치된다. [Spine 슬롯과 그리기 순서](https://esotericsoftware.com/spine-slots)

```text
19 eye_white_screen_left
20 eye_white_screen_right
   clip_iris_l  → End slot = iris_screen_left
21 iris_screen_left
   clip_iris_r  → End slot = iris_screen_right
22 iris_screen_right
23 upper_lid_screen_left
24 upper_lid_screen_right
```

- `clip_iris_l`에는 `aperture-left`, `clip_iris_r`에는 `aperture-right`를 사용한다. 각 36점을 `head` 본 기준 좌표로 바꾼다. 예를 들어 왼쪽 다각형의 첫 점 `(245, 546)`은 `head` 피벗 `(550, 757)` 기준 **`(-305, 211)`**이다.
- 클립은 머리와 같이 움직인다. 홍채 본을 옮겨도 클립의 위치는 흰자에 고정된다. 각 클립 범위는 자기 홍채 슬롯에서 끝나도록 지정한다. [Spine 클리핑과 End slot](https://esotericsoftware.com/spine-clipping)

## 3. 검수와 저장

1. **셋업** · 32개 이미지 슬롯과 두 클립이 있고, 얼굴 표정·앞머리·의상·팔다리의 위치와 앞뒤가 `setup-pose.png`에 맞는지 확인한다. `layout.json`의 하트는 그리기 순서 31이다.
2. **시선과 고개** · 고개를 약 3° 돌리고, 포니테일을 머리 기준 약 8° 흔든다. 홍채를 원본 캔버스 기준 왼쪽 9px, 아래 4px 정도 옮겨도 두 흰자 영역 밖으로 새지 않는지 본다.
3. **팔다리** · 오른팔 팔꿈치 약 17°, 양 무릎 약 9°에서 관절이 겹쳐지는지 확인한다. `motion-check.png`는 이 정도 각도의 참고 이미지다. 실제 모션에서 선의 단차나 빈틈이 눈에 띄면 회전축과 겹침을 조정하고, 필요한 경우 SVG에서 해당 부분만 수정한 뒤 PNG 및 좌표를 함께 갱신한다.
4. **납품** · 새 `.spine` 파일과 연결된 `images/`, 기준 포즈 캡처를 한 위치에 둔다. 본·클립 테스트는 짧은 `rig_check`로 저장해 두면 검수하기 쉽다. 저장한 프로젝트를 다시 열어 누락된 이미지가 없는지 확인한다.

게임용 내보내기까지 이어갈 경우, 현재 작업공간은 `project.godot`가 있는 Godot 프로젝트다. 사용할 Spine 런타임과 에디터의 주·부 버전을 확인한 다음 데이터 형식과 아틀라스를 결정한다. 이 인수인계의 기준 결과물은 조립된 Spine 프로젝트다. [Spine 에디터와 런타임 버전](https://esotericsoftware.com/spine-versioning)
